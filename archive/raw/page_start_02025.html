In this post, I would like to explain another thing about polynomial regression. There are two types of data for polynomial regression. One type of data is totally random and we do not know what is the associated value of CDF (in continuous terms) with precision since data is not equi-spaced with respect to any metric. For this type of data, we sorted it and associated an equi-probable normal array (equal to data length) and we also matched the moments of this equi-probable normal array.  And then we followed with regression to find coefficients of Z-series. This is the case in our program when we try to find individual Z-series coefficients of asset data paths (all of the asset paths that lie in the particular volatility grid subdivision) associated with each of the volatility grid subdivisions.

Second type of data where we can also use LS regression is where we already know the underlying normal array associated with each data element with perfect accuracy(for many reasons since data might have been created from a known array of underlying normal density or so on), I call this case as non-randomly distributed data since as opposed to randomly distributed data discussed in previous paragraph, we know the value of underlying normal array associated with each data member with precision.  I am of the opinion that in such a case, we might not need to match moments of underlying normal density array since we already know the true values of underlying array from normal density associated with data elements. This is the case in our program when we are trying to find universal coefficients of each of the Z-series coefficients and we know the value of particular Z-series coefficient associated with individual volatility grid points where we know CDF associated with each volatility grid. 

This is how I am treating different types of data in my program but urge friends to think on their own what would be the right way to tackle both kinds of data and when would we need to match moments of associated normal array with true moments and when we would not need to match moments of underlying normal array associated with the data.

Friends, I want to make several major changes to the program.
I noticed that Z-series coefficients constructed from coeffs of coeffs behave well in the range that was used to construct them. i.e. between Zv=-2.5 to Zv=+2.5 but outside of that range they can be quite off. We get reasonable graphs and call prices since probability out side of this range is very small. But I want to improve this.
I used equi-probable underlying Z-grid for calculation of coeffs of coeffs and I want to see how to improve it or change it to equi-distant grid or some other method in between. 
I am also thinking of standardizing every asset density conditional on each volatility grid cell and then model volatility(that appears in standardization of every conditional asset density) as a separate Z-series and finds coeffs of coeffs for standardized densities. Final Z-series of conditional asset densities could be constructed as a product of volatility Z-series and coefficients constructed from coeffs of coeffs (found from standardized conditional densities). 
Another thing I was thinking about polynomial regression. When we know both Z and probability associated with an observation as in case of an underlying grid, we could also use a weighted LS regression(weighted by probability associated with each observation or grid cell etc.) instead of a plain LS regression. Even if we do not use probabilities as weights, it would still be useful to find some other way of giving large weights, in polynomial regression, to mid-density and small weights to far-tails.

I also start to believe that many times when Z-series density folds back onto itself, it can still be meaningful and might have some non-linear dynamics for Z-series variables. In such cases, our simple method to construct the density is not good at all but it will be far more meaningful in such cases to draw a graph of random variable X(constructed by Z-series) as a function of Z in the Z-series. I noticed that graphs of densities of coeffs found from Z-series of coeffs of coeffs were quite absurd but when I plotted coeffs as a function of underlying Z, I still found those graphs quite meaningful and informative. I think it very informative whenever we graph a density from Z-series that we also graph X as a function of Z.
Basically when density folds onto itself, it means that X is not monotonically increasing as a function of Z which is a perfectly valid possibility and such dynamics might exist many times in reality. Moments of density folding onto itself might still be matching perfectly with input moments. In such cases our method of density construction is not good and it has to be re-written with a better mathematical logic. However if we do want X as a monotonically increasing function of Z explicitly, these densities might not be of our use.

I am trying to make it a good program and it can still take sometime. Sorry to make friends wait for the final program.
