Friends, I will post my matlab files sometime tonight. I am sure friends are already familiar with most of the ideas I used since I have described them in the thread earlier. However there are some things that I want to describe again even though I have previously mentioned them.
In the program, I first calculated coefficients of conditional asset Z-series associated with each volatility grid subdivision separately. And I want to describe its details and other related ideas.
First I transformed the stochastic volatility variable to bessel-like coordinates by using the formula   [$]W\, = \, V^{(1-\gamma)}[$]. I would like to mention that this transformation preserves the probability mass within each grid cell and also CDF along the grid cells when compared with stochastic volatility variable in original coordinates. This was done to find a more normal-like grid for our analytics of Z-series calculations. There was no issue since underlying Z, ([$]Z_w(n)\, = \, Z_v(n)[$]) would be the same for all of the arbitrary nth grid cells as CDF remains the same across respective grid cells even after transformation. 
First I put together all of the asset paths from monte carlo that lied in a particular stochastic volatility grid cell/subdivision.
My first approach was to find the moments of asset paths lying in a particular SV grid cell and convert them into Z-series associated with our original algorithm of calculating Z-series from first seven moments. But it was working very poorly due to large noise in moments. 
I then tried polynomial regression on the values of asset paths lying in a particular grid subdivision. Here I will take a minute to give friends idea about polynomial regression as I did it. 
We know that in a particular monte carlo run, the probability weight associated with each monte carlo path is reciprocal of total number of monte carlo paths. We could do a polynomial regression (of monte carlo data on first few hermite polynomials) on a collection of monte carlo paths, if we could associate corresponding values of hermite polynomials to each of the monte carlo paths. Then we would pair each monte carlo path with set of associated hermite polynomials and run the regression to find common coefficients of hermite polynomials. 
Problem is that hermite polynomials are derived from normal distribution and there is no obvious way to associate hermite polynomials values with data values of monte carlo paths. 
But we can relate them with each other through probability values. As I earlier mentioned that  in a particular monte carlo run, the probability weight associated with each monte carlo path is reciprocal of total number of monte carlo paths [$]\frac{1}{N_p}[$] . We can divide the normal density into equal probability weight subdivisions with total number of subdivisions equal to monte carlo paths [$] N_p [$] and probability of each subdivision equal to probability of each monte carlo path [$]\frac{1}{N_p}[$]. Suppose the center of each equal probability normal density subdivision is [$]Z_n[$]. Then we sort all the monte carlo paths and assign each of the data values [$]X_n[$] to hermite polynomials based on [$]Z_n[$] as given by [$]H_m(Z_n)[$]. So now we are able to pair, for linear regression, the set of polynomial values   [$]H_m(Z_n)[$] with each of the associated data value [$]X_n[$] and run the regression.
Again probability subdivisions in normal density equal in number to monte carlo paths and the probability associated with each normal density subdivision is equal to probability associated with each monte carlo path. We then relate the Z_n associated with center of each normal density subdivision with sorted value X_n of the monte carlo data.
I have previously briefly described this procedure earlier in posts 1817, 1818, 1819, 1820 and 1822.
The polynomial regression method was very robust as compared to matching moments method for noisy data. Earlier I was trying all of this with 7th order Z-series but for the kind of problems I was playing, I noticed that 7th order Z-series was an overkill and I worked later with 5th order Z-series and robustness further increased with polynomial regression method. However I never tried moment matching method with 5th order Z-series. And for friends who would want to try very high volatility for longer periods of time, you may have to actually use a 7th order Z-series for accuracy. But using 7th order Z-series for problems that only require 5th order Z-series causes decrease in robustness of the method.
For polynomial regression, our matrix formulation is 

[$] X\,=\, H \, \beta \ + \epsilon[$] 

Where X is a N X 1 vector of asset values associated with sorted monte carlo paths in increasing order. Here N is total number of monte carlo paths that lie in a particular stochastic volatility grid subdivision.
H is a N X (M+1) matrix of hermite polynomials calculated from Z_n associated with nth equal probability subdivision of normal density in increasing order. M is the order of highest hermite polynomial and 1 is added for a constant associated with zeroth order hermite polynomial.
[$]\beta[$] is a M+1 X 1  vector of ceoefficient of hermite polynomials in Z-series to be found from regression.
Our hermite Series for the data random variable X, now would be

[$] \, X \, = \, \beta_0 \, + \beta_1 \, Z \, + \beta_2 \, H_2(Z)+ \beta_3 \, H_3(Z)+ \beta_4 \, H_4(Z)+ \beta_5 \, H_5(Z)[$]

Also for reference of friends, I tried to improve the value of Z_n so that moments of the equal probability subdivisions density match with normal moments since I am trying to use discrete values of Z_n. For paths greater than 100, this is not a problem at all but for very small number of paths i.e close to twenty paths, this might be a minor issue. Mostly this is a very slight correction to Z_n values and this correction decreases fast as number of paths increase. 
So this is how I was able to generate relatively robust values of numerically calculated Z-series coefficients associated with each stochastic volatility grid.
I still want to play around with matching moments method since I want to see if in a decreased order Z-series (as I decreased the Z-series order from seven to five), moment matching method might be competitive with above regression method but I have to play  with program further to see this.
Again regression method works very well especially as number of monte carlo paths (or data values in a data set) increase.
In the next post, I will describe how I converted the separate coefficients of above numerically calculated Z-series into one single analytic universal Z-series for each of the coefficients. However, a robust calculation of individual numerically calculated Z-series was a pre-requisite for the later method to work well and that is what I have described in this post.

    zeta*(ZI(1:Ndata).^4-6.*ZI(1:Ndata).^2+3));

%one for Z smaller than zero.

%lower values between which it can be found.

%than Y(.5), we know that true value of Y will lie between 0 and .5
%so we assign a lower band value Za=0 and upper band value Zb=.5

%than .5 and we again evaluate Y(1) at Z=1, If Y is smaller than Y(1), 
%we know that true value of Z should be between .5 and 1, and we assign a 
%lower band value Za=.5 and upper band value of Zb=1. Through repeated 
%elseif we continue until we find an appropriate band value of Z.

%move the upper band to Zb=Zmid while keeping Za at older value. However if

    if(Y< EvaluateZSeriesC5(c0,c,.5))

Friends, I want to share the details of my small algorithm to correct the moments of arrays of standard normals associated with equiprobable normal grid subdivisions. These arrays of standard normals would later be used for polynomial regression on the data to find parameters of Z-series from the data.

Suppose there are N data members and we want to do a hermite polynomial regression on this data to find Z-series parameters of data random variable. We will divide the standard normal density into N subdivisions with each subdivision sharing an equal probability mass of 1/N.
However discrete values of Zn when integrated on probability mass 1/N, can have moments different from moments of standard normal density which will create inaccuracies in our polynomial regression to find Z-series parameters of the data random variable.

I thought of multiplying the data array with an expression comprising sum of hermite polynomials with unspecified coefficients. We would write equations of moments and then find coefficients of hermite polynomials that pin down the  moments of new data precisely equal to target moments.

One consideration is that our Zn array is perfectly symmetric around zero so all odd moments are zero. We want to add only even hermite polynomials in the expression of hermite polynomials with unspecified coefficients(that is multiplied to original Zn array to make its moments equal to target moments). We do not want odd hermite polynomials in this expression with unspecified coefficients as they would introduce skew in our array of equi-probable standard normal values(and then we would have to do unnecessary work to cancel the skew). In order to have zero odd moments(as in case of standard normals), we only multiply with a series in even hermite polynomials with unspecified coefficients that preserves perfect symmetry around zero so we would not have to bother with any odd moments and all odd moments will be zero by construction due to symmetry of our Zn array around zero.

Our original standard normal Zn array associated with equiprobable grid is multiplied with a series in hermite polynomials as

[$]Z_{n,Corrected} \, = \, Z_n \, (\alpha \, +  \beta \, (Z_n^2-1) \, + \, \gamma \, ({Z_n}^4 \, + \, 6 \, {Z_n}^2 \, + \, 3 \,))\,[$]
 
We find coefficients [$]\alpha[$], [$]\beta[$], and [$]\gamma[$] so that our objective function matching moments of [$]Z_{n,Corrected} \, [$] with target moments is maximized.

[$]Moment2\, = \sum\limits_{n=1}^{n=N} \, {Z_{n,Corrected}}^2 \, \frac{1}{N} [$]
