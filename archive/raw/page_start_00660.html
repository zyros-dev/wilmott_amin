Ok, one more important thing that you cannot have an explicit t or its powers in the SDE and it can solve the most of the SDEs of the type that usually appear in math finance usually with only dt. Code: Select all
Clear[x, x0, Y, p, l1, l2, Z, mu, sigma, mu0, sigma0, k, m, ll1, ll2, YAns, H];
p = 4;
ll1 = 0;
ll2 = 0;
Array[Y, {p + ll1 + 1, p + ll2 + 1}, {0, 0}];
For[k = 0, k <= p + ll1, k++, (For[m = 0, m <= p + ll2, m++, (Y[k, m] = 0);]);];
Y[ll1, ll2] = x;
mu := mu0 *x;
sigma := sigma0*x;
For[k = 0, k < p, k++, (For[m = 0, m <= k, m++,(l1 = ll1 + k - m; l2 = ll2 + m; 
Y[l1 + 1, l2] = Y[l1 + 1, l2] + D[Y[l1, l2], x]*mu + .5*D[D[Y[l1, l2], x], x]*sigma^2;
Y[l1, l2 + 1] = Y[l1, l2 + 1] + D[Y[l1, l2], x]*sigma;)];)];
Array[H, p + ll2 + 1, 0];
YAns = 0;
For[k = 0, k <= p, k++, (For[m = 0, m <= k, m++,
     (l1 = ll1 + k - m; l2 = ll2 + m; 
      YAns = YAns + Y[l1, l2]*Sqrt[(t^(2*l1 + l2)*(2*l1)!)/((2*l1 + l2)! (l1!)^2)]*H[l2]/Sqrt[l2!];)];)];

Sometimes I think that such a method should probably be called hermite transform method to solve the SDEs because I think that they are in some sense analogous to what sine and cosine with different frequencies are to fourier transforms and I am sure some of the similar problems might arise when we integrate higher order hermite polynomials just like the sort of problems arise when high frequencies are integrated in fourier transforms. We can of course know that hermite polynomials are orthogonal basis functions just like sines and cosines with different frequencies are basis functions for fourier transforms. An obvious difference is that high frequencies in fourier are mostly seen in short term options. But comparing with fourier transforms, we see that as fourier with zero frequency gives us the mean, here hermite polynomial of order zero gives us the mean. It seems that many times it could possibly be more important to get lower order hermite polynomials right as compared to adding larger order hermite polynomials. May be we can take series in hermite polynomials upto possibly eighth order and take larger number of terms so that coefficient terms with each of these low order hermite polynomials converge. Taking the extreme case, we can see if series of terms with hermite polynomial of order zero does not coverge we will never have a right distribution since mean will be off even if we have included the 32nd order hermite polynomials in the expansion. But this would have to be very carefully seen and properly researched. But we can probably do a rough analysis of convergence once we know how and when the time coefficients that arise from the integration and calculation of variance converge and when factorial takes over the higher order powers of terminal time and based on that and combined with already calculated coefficients of hermite polynomials a simple analysis of convergence could be possible. Though lack of convergence in coefficient terms of higher order hermite polynomials would be a problem but lack of convergence in the series of terms which are coefficients of lower order hermite polynomials would be a far larger problem.
With the current expansion, I do not believe that it would be possible to solve all the SDEs universally with something like hermite polynomials to 16th order which could possibly work only till a year in some of my simulations. I am posting new code derived from the earlier code posted on this forum. One difference is that array limits and loop count limit parameters are written in capitals letters. L1 replaces ll1 and L2 replaces ll2. This new code expands to P1 order while keeping terms till P2 hermite polynomials. P1=8 and P2=4 will mean that there will be only coefficients of first four hermite polynomials and total expansion will be taken to eighth order. You can specify a large P1 while retaining first four or eight hermite polynomials. You could do a rough convergence analysis on the dt-integrals for a given t and find out when pure drift would converge and use that to find a rough bound on P1 order. Here is the code.
Code: Select all
Clear[x, x0, Y, P1, P2, l1, l2, Z, mu, sigma, mu0, sigma0, k, k1, m, L1, L2, YAns, H];
P1 = 8;
P2 = 4;
L1 = 0;
L2 = 0;
Array[Y, {P1 + L1 + 1, P2 + L2 + 1}, {0, 0}];
For[k = 0, k <= P1 + L1, k++, (For[m = 0, m <= P2 + L2, m++, (Y[k, m] = 0);]);];
Y[L1, L2] := x;
mu := mu0*x;
sigma := sigma0*x;
For[k = 0, k < P1, k++, (For[m = 0, m <= If[k <= P2, k, P2], m++,(l1 = L1 + k - m; l2 = L2 + m; Y[l1 + 1, l2] = Y[l1 + 1, l2] + 
        D[Y[l1, l2], x]*mu + .5*D[D[Y[l1, l2], x], x]*sigma^2;
If[l2 < L2 + P2,(Y[l1, l2 + 1] = Y[l1, l2 + 1] + D[Y[l1, l2], x]*sigma), 0])];)];
Array[H, P2 + L2 + 1, 0];
YAns = 0;
For[k = 0, k <= P1, k++, (For[m = 0, m <= If[k <= P2, k, P2], m++,(l1 = L1 + k - m; l2 = L2 + m; 
      YAns = YAns + Y[l1, l2]*Sqrt[(t^(2*l1 + l2)*(2*l1)!)/((2*l1 + l2)! (l1!)^2)]*H[l2]/Sqrt[l2!];)];)];

Ok, here is the code for this SDE

dX= mu0 X^beta *dt + sigma0 * X^gamma *dz(t)

It will solve for the functions of the kind f(x)=a0* X^alpha; of the SDE. It will not find solution for higher order integrals and will solve only for the SDE or its functions. I will post a revised version of the code which can find solution for any order of integrals tomorrow. I am presenting two mathematica routines. One which I had posted earlier and this new one. This code is based only on arithmetic and some algebra and there is no need for any calculus. I will substitute values of all parameters to get a result solely in terms of hermite polynomials and their numerical coefficients. You could compare and find that solution is same from the code that is based on calculus and the other one that is based on arithmetic and some algebra.
This is just first intermediate version. The second version will be able to take two terms in drift for non-linear dynamics and will also be able to solve for all higher order integrals. There is a three dimensional array of coefficients that keeps track of drift terms, quadratic variantion terms and volatility terms and their all possible combinations.

Here are the parameters of the examples.
mu0=.25, beta=1,sigma0=.75, gamma=.75, x0=.75, t=.25, alpha=2.0, a0=1;
or alternatively we have
f(X)=X^2
and SDE is
dX=.25*X dt+ .75 * X^.75 *dz(t)
X0=.75;

Here is the arithmetic based code which just finds the coefficients and then multiplies them to appropriate powers later.
Code: Select all
Clear[x, x0, Y, P1, P2, l0, l1, l2, l3, Z, mu, sigma, mu0, sigma0, k,k1, m, n, L1, L2, YAns, H];
P1 = 8;
P2 = 4;
L1 = 0;
L2 = 0;
Array[Y, {P1 + L1 + 1, P1 + L1 + 1, P2 + L2 + 1}, {0, 0, 0}];
For[k = 0, k <= P1 + L1, k++, (For[m = 0, m <= P1 + L1, m++, (For[n = 0, n <= P2 + L2, n++, (Y[k, m, n] = 0);]);]);];
Y[L1, L1, L2] := a0 ;
For[k = 0, k < P1, k++, (For[m = 0, m <= If[k <= P2, k, P2], m++,(l0 = L1 + k - m; l3 = L2 + m; 
       For[n = 0, n <= l0, n++, (l1 = l0 - n; l2 = L1 + n; Y[l1 + 1, l2, l3] = 
          Y[l1 + 1, l2, l3] + Y[l1, l2, l3]*(alpha + l1*beta + l2*2*gamma + l3*gamma - l1 - 2*l2 - l3)*mu0; 
         Y[l1, l2 + 1, l3] = Y[l1, l2 + 1, l3] + Y[l1, l2, l3]*.5*(alpha + l1*beta + l2*2*gamma + l3*gamma - l1 - 2*l2 - l3)*(alpha + l1*beta + l2*2*gamma + l3*gamma -l1 - 2*l2 - l3 - 1)*sigma0^2;
         If[l3 < L2 + P2,(Y[l1, l2, l3 + 1] = Y[l1, l2, l3 + 1] + Y[l1, l2, l3]*(alpha + l1*beta + l2*2*gamma + l3*gamma - l1 - 2*l2 - l3)*sigma0), 0])];)];);];
Array[H, P2 + L2 + 1, 0];
YAns = 0;
For[k = 0, k <= P1, k++, (For[m = 0, m <= If[k <= P2, k, P2], m++,(l0 = L1 + k - m; l3 = L2 + m; 
       For[n = 0, n <= l0, n++, (l1 = l0 - n; l2 = L1 + n; 
         YAns = YAns + Y[l1, l2, l3]*x^(alpha + l1*beta + l2*2*gamma + l3*gamma - l1 - 2*l2 - l3)*Sqrt[(t^(2*l1 + 2*l2 + l3)*(2*l1 + 2*l2)!)/((2*l1 + 2*l2 + l3)! ((l1 + l2)!)^2)]*H[l3]/Sqrt[l3!];)];)];);];
YAns /. {alpha -> 2, beta -> 1, gamma -> .75, a0 -> 1, sigma0 -> .75, mu0 -> .25, x -> .75, t -> 1.25}

Here is the modified program that will work for dz and dt-integrals of all order. It is the same SDE but with modified parameters. The program is re-written  to become faster since values of SDE and related parameters that are used in the algorithm are assigned before the start of the algorithm. When I tried assigning values yesterday after the computations, mathematica was sometimes still taking a long time. Now it works very fast. This algorithm can very easily be ported to C++ etc.
Code: Select all
Clear[x, x0, Y, P1, P2, l1, l2, Z, mu, sigma, mu0, sigma0, alpha, beta, gamma, a0, k, k1, m, L1, L2, YAns, H];
P1 = 16;
P2 = 8;
L1 = 2;

Here is a small algorithm to generate hermite polynomials in matlab, c++ or Python etc.
Hermite polynomials have recursion relation H[n+1]=Z*H[n]-d/dZ[H[n]];  here n is the order of hermite polynomials.
In my program Hz symbolizes coefficients of hermite polynomials. It is a two dimensional array and contains coefficients of hermite polynomials where first index indicates order of hermite polynomials and second index indicates the power of Z. So Hz[k,m] will contain coefficients of  Z^m in k-th hermite polynomial. 
Recursion algorithm is very simple. In order to mimic the first term in recursion relation Z*H[n], the coefficient of mth power in kth polynomial will go to coefficient of m+1-th power in k+1 order hermite polynomial, i.e coefficient of Z^m in k-th hermite polynomial will go to Coefficient of Z^(m+1) in k+1-th hermite polynomial. This is done using the command Hz[k + 1, m + 1] = Hz[k, m];
Second term in recursion is -d/dZ[H[n]], so here we multiply the m th coefficient of kth hermite polynomial by m and add it to (m-1)-th power of k+1-th order hermite polynomial. This is done by algorithm as  Hz[k + 1, m - 1] = Hz[k + 1, m - 1] - m*Hz[k, m];  This is done because coefficient of  Z^(m-1) in k+1-th hermite polynomial is given by (m*Coefficient of Z^m) in k-th hermite polynomial . 
The numerical multiples of these hermite polynomials have already been calculated in the previous program.   After getting the result in terms of powers of Z, you simply have to draw a graph after calculating the derivative associated with change of variable in the normal density. I would have loved to do that but was facing bizarre problems in that and would try to post that tomorrow.
